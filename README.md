# final-exam
ფინალური ნაშრომი

 
 მოცემულ ნაშრომში შესრულდა ხუთი ამოცანა, რომელთაგან თითოეული მათგანი მიმართული იყო კრიპტოგრაფიის საკვანძო პრინციპების პრაქტიკულ გამოყენებაზე. 
 
 პირველი ამოცანა მიზნად ისახავდა დაშიფრული მესიჯინგის სისტემის შექმნას RSA და AES ალგორითმების კომბინაციით. მომხმარებელმა A დააგენერირა RSA საჯარო და პირადი გასაღებების წყვილი, ხოლო მომხმარებელმა B შექმნა საიდუმლო შეტყობინება, რომელიც დაშიფრა AES-256 ალგორითმით. AES გასაღები დამატებით RSA-თ დაიშიფრა, რის შედეგადაც მომხმარებელმა A-მ შეძლო დაშიფრული AES გასაღების განშიფვრა პირადი RSA გასაღებით და საბოლოოდ შეტყობინების განშიფვრაც. შედეგად შეიქმნა შესაბამისი ფაილები და README დოკუმენტი, რომელიც აღწერს დეტალურად დაშიფვრის პროცესს.
 
 მეორე ამოცანაში განხორციელდა ფაილის დაცული გაცვლის პროცესი ჰიბრიდული დაშიფვრით. ამ ამოცანაში ყურადღება გამახვილდა მონაცემების მთლიანობის გადამოწმებაზე. ალისმა შექმნა დაშიფრული ფაილი AES-256 და RSA კომბინაციით, შემდეგ კი გაგზავნა ბობთან  დაშიფრული AES გასაღებით. ბობმა განშიფრა AES გასაღები RSA პირადი გასაღებით და წაიკითხა შეტყობინება. ორივე ვერსიის SHA-256 ჰეშის შედარებით დადგინდა მონაცემების მთლიანობა.
 
 მესამე ამოცანა მდგომარეობდა TLS კომუნიკაციის ანალიზში openssl და Wireshark-ის გამოყენებით. განხილულ იქნა TLS პროტოკოლით კლიენტ-სერვერ კომუნიკაციის ძირითადი ეტაპები: Client Hello, Server Certificate და Key Exchange. ასევე, გამოყოფილ იქნა სერტიფიკატების ჯაჭვი და გამოყენებული ციფრული ალგორითმი. ასევე გაანალიზებულ იქნა TLS-ის კონფიდენციალურობისა და მთლიანობის მექანიზმები - როგორიცაა სიმეტრიული დაშიფვრა და HMAC.
 
 მეოთხე ამოცანაში წარმოდგენილია ელფოსტის უსაფრთხოების სიმულაცია PGP და S/MIME მეშვეობით. GPG-ის გამოყენებით გენერირდა გასაღებების წყვილები ალისა და ბობისთვის. ალისმა ხელმოწერა და დაშიფვრა გაუკეთა შეტყობინებას, ხოლო ბობმა მოახდინა დეშიფრაცია და ხელმოწერის ვალიდაცია. გენერირდა შესაბამისი ფაილები და ტექსტურ დოკუმენტში გაიწერა იმის ახსნა, თუ როგორ ამოწმებს ხელმოწერა გამომგზავნის ავთენტურობას.
 
 მეხუთე ამოცანაში შემუშავდა Python სკრიპტი, რომელიც მოცემულ ფაილზე აგენერირებდა SHA-256, SHA-1 და MD5 ჰეშებს და ინახავდა .json ფორმატში. შემდეგ მოხდა ფაილის მოდიფიკაცია, ჰეშების ახლიდან გამოთვლა და ორ კომპლექტს შორის შედარებით გამოვლენილ იქნა ცვლილება. სკრიპტმა სწორად დააფიქსირა დარღვევა და მომხმარებელს გამოუტანა გაფრთხილება მთლიანობის დარღვევის შესახებ.
